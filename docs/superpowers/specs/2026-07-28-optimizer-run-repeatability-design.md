# Optimizer run repeatability

## Goal

For a fixed matrix, optimizer, dependency environment, configuration, and phase
seed, repeated executions must produce the same candidate batches, objective
costs, selected paths, and final matrix.

The contract applies to:

- `scripts/base_search/full_pso.py`
- `scripts/base_search/full_cmaes.py`
- `scripts/base_search/full_de.py`
- their shared evaluation and archive logic in
  `scripts/base_search/full_optimizer_common.py`

## Determinism boundary

The implementation guarantees repeatability when the Python, NumPy, SciPy,
PySwarms, CMA, compiler, and native-library versions are unchanged.

Cross-version and cross-platform floating-point differences are allowed.
Execution-time statistics and deadline-triggered interruption are also allowed
to differ because they intentionally depend on wall-clock time.

## Root cause

The initial PSO population is generated by a seeded SciPy Latin-hypercube
sampler, but PySwarms obtains its initial velocities and per-iteration
cognitive/social random values from NumPy's process-global RNG. The current PSO
entry point never resets that RNG. Therefore identical initial positions can
produce different velocities and diverge after the first evaluated iteration.

CMA-ES and differential evolution already receive explicit seeds, but resetting
all supported optimizer RNG sources at each phase gives them the same
run-isolation contract and protects against process-global random state consumed
before an optimizer starts.

## Design

Add a shared function in `full_optimizer_common.py` that accepts an integer
phase seed and resets:

1. Python's process-global `random` stream.
2. NumPy's legacy process-global random stream used by PySwarms and CMA.

Each optimizer calls the helper immediately before constructing or invoking its
third-party optimizer:

- PSO uses `PSO_RANDOM_SEED + phase`.
- CMA-ES uses `CMA_RANDOM_SEED + phase` and retains its existing CMA `seed`
  option.
- Differential evolution uses `DE_RANDOM_SEED + phase` and retains its private
  `numpy.random.default_rng` instance.

Latin-hypercube initialization keeps its existing private seeded generator.
No optimizer hyperparameters, budgets, population sizes, score formulas, or
thread counts change.

## Threading and ordering

`BatchObjective` keeps parallel particle evaluation. `ThreadPoolExecutor.map`
returns results in input order, and those results are merged in that same order.
Each particle uses an evaluator clone with independent mutable policy state.
The shared path and native matrix are read-only during evaluation, while the
native policy wrapper constructs per-call matrix data.

Seed-level results remain sorted into seed order before being recorded. No
completion-order data participates in optimizer costs or archive insertion.

## Tests

Add regression coverage for:

1. Resetting the shared optimizer seed reproduces both Python and NumPy random
   sequences after unrelated draws perturb their global state.
2. Two PySwarms optimizers constructed from identical initial positions after
   the same phase reset have identical initial velocities.
3. PSO, CMA-ES, and differential evolution invoke the shared reset with their
   phase-specific seed.
4. Existing optimizer, evaluator timing, and standard-run tests continue to
   pass.

The tests must first fail against the current implementation before the helper
and optimizer calls are added.

## Non-goals

- Replacing PySwarms, CMA, SciPy, or NumPy.
- Producing bit-identical trajectories across dependency versions or CPU
  architectures.
- Making wall-clock timings identical.
- Making a run terminated by a soft deadline independent of scheduling speed.
- Changing native policy sampling or scoring behavior.
